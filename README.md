# יאללה־סע · נסיעות ריקות (מודול, מפעילים כדיירים)

- פתיחה: `index.html` (או שרת מקומי: `python -m http.server 8770 --directory dashboard`).
- כניסה: שם משתמש וסיסמה (בלי מייל בכלל; מאחורי הקלעים Supabase Auth עם כתובת פנימית `<username>@users.yalla-sa.app` שלא מוצגת ולא מקבלת מיילים). אין הרשמה עצמית ואין שחזור סיסמה עצמי.
- חשבון מנהל ראשי: נוצר פעם אחת ממסך הכניסה (כשעוד אין). אחר כך הטופס נעלם לתמיד (נאכף בשרת).
- "חדר בקרה": יצירת משתמש עם סיסמה זמנית, הרשאה ומפעיל, סיסמה זמנית חדשה, השבתה, מחיקה (Edge Function `manage_users`). מנהל מפעיל רואה רק את המשתמשים של המפעיל שלו. סיסמה זמנית חייבת להיות מוחלפת בכניסה, ועד אז אין גישה לנתונים.
- הרשאות: צופה / עורך / מנהל מפעיל, ומנהל מערכת. מנהל מערכת יכול למנות/להסיר מנהלי מערכת ולקבוע סיסמה זמנית לכל משתמש חוץ מעצמו; תמיד נשאר לפחות מנהל מערכת פעיל אחד (נאכף בשרת).
- החשבון שלי (לחיצה על השם בכותרת): "שינוי סיסמה" לכל משתמש. למנהלי מערכת גם "שחזור חשבון": קודי שחזור חד־פעמיים (נשמרים רק כ־hash) ומייל לשחזור (אופציונלי, דרך השולח המובנה של Supabase). במסך הכניסה: "אין לי גישה (קוד שחזור)", ו"שכחתי סיסמה" רק לחשבון עם מייל. ניסיונות מוגבלים לכל שם משתמש, וכל אירוע נרשם (`private.auth_events`). דרך הבעלים: `../החלפת-סיסמה.md`.
- מפעילים: `pipeline/operators.json` (פעיל / לא פעיל, גבול יום שירות, סוד מפתח הנתונים). נתונים לכל מפעיל ב-`data/<slug>/`.
- `legacy.html`: הפניה לדף הראשי (הכניסה בסיסמה המשותפת הוסרה).
- עדכון אוטומטי: כל לילה ה-Action `nightly-day` מוסיף את יום אתמול לכל מפעיל פעיל. מילוי ימים חסרים: Actions → nightly-day → Run workflow עם from/to (ו-operator).
- הוספת יום ידנית: `python dashboard/build_day.py YYYY-MM-DD --op derech-egged` (הקוד ב-`pipeline/`; דורש `config/.data_key_<slug>` ו-`pip install tzdata`).
- קישור ישיר: `index.html?op=derech-egged&day=2026-11-10&veh=23404402`.
- **מקור המיקומים והזמנים:** נקודת ה־GPS הראשונה והאחרונה של כל נסיעה ב־SIRI (Open Bus). נסיעה קצרה מאוד שאחריה מיד אותו קו = "התחלה כפולה" (אוחדה, לא נסיעה ולא תגבור). נסיעה שלא הגיעה לסוף הקו = "לא הושלמה לפי GPS" (נספרים הק״מ שנסעה). נסיעה בלי שום מיקום תקין ומשך 0 = "לא בוצעה" (לא נספרת). בלי GPS בכלל: לפי הלוח, ומסומן. הספים בראש `pipeline/build_day.py`.
- **לילה = ישות אחת:** הבחירה ללילה נשמרת על היום שאחריו (`overnight_override.day`), ושני הימים קוראים אותה. כל רגל נספרת פעם אחת, ביום שבו נסעה (חזרה לחניון ביום הקודם, יציאה ביום הבא). גם אחרי ימים בלי פעילות (עד 14 יום). קצוות הטווח מסומנים "לילה פתוח". המודל המשותף: `assets/core.js` (גם הבודק משתמש בו). המיקומים בין הימים: `data/<slug>/ends_<YYYY-MM>.js` (מוצפן, נבנה מחדש מקובצי הימים).
- **טיוטה ושמירה:** כל שינוי (הגדרות, תגבור, לילה, סניף, תגבור אוטומטי) משנה מיד את התצוגה, ונכתב רק בלחיצה על "שמירה" בכותרת (`save_changes`, טרנזקציה אחת). מעבר יום לא שואל ולא מוחק טיוטות. שאלה "לשמור?" רק ביציאה מהמערכת, בסגירה או רענון, ובמעבר לרכב אחר.
- **עריכת סידור ידנית (תיקון שגיאות נתונים):** בחלונית הרכב "✎ עריכת הסידור" (גם מכל התראה על נתון חשוד): מחיקה, החלפה בקו מהרשימה, שינוי שעות, הוספת נסיעה, העברה לרכב אחר. כל עריכה = שורה ב־`block_edits` (טיוטה עד "שמירה"), מסומנת "נערך ידנית" עם מי ומתי, ניתנת לביטול אחת־אחת; "הצג מקור" מראה את הנסיעות המקוריות. `assets/core.js applyBlockEdits()` בונה מחדש את הסידור הערוך (ריק לפי כביש, סכומים, תחילה וסוף), וכל השאר (לילות, כרטיסים, סניף, הבודק) מחושב ממנו. מנוע ההצעות מקבל את אותו דבר דרך `window.YS_HOST.getBlocks(day)`.
- **גרסה:** לפני כל שינוי ב־`index.html` או ב־`assets/` מריצים `python tools/bump_version.py`. דפדפן עם גרסה ישנה נטען מחדש פעם אחת.
- **בודק:** `python ../audit/check_invariants.py` (מחוץ למאגר) מריץ את המודל על כל הימים: 0 הפרות = תקין.
- הגדרות (גלגל השיניים): "הגדרות מערכת" (חניונים, דלק, נקודות החלפה, סניפים, ברירות מחדל, רכבים) ו"הגדרות תצוגה" (בהמשך). נשמרות ב-Supabase לכל מפעיל (דרך הטיוטה וכפתור "שמירה"). שורת חניון שומרת שדות נוספים, כך שקיבולת וכדומה ייכנסו בלי שינוי מבנה.
- לוגו מפעיל: `assets/operators/<slug>.png` ו-`operators.logo_url`.
- רפרנס עיצוב מאושר: `design/reference-v1.webp`.
- **בדיקת מסלול (`assets/route.js`, משותף לדפדפן ול־pipeline דרך `pipeline/route.js`):** OSRM לפעמים "נצמד" לכביש הלא נכון ליד מסוף (למשל מסוף ארזים → כביש 1 ופרסה: 27.75 ק״מ במקום ~10–13). מסלול נחשב חשוד אם יש בו פרסה, אם הוא חוזר לכביש ממוספר שכבר עזב, אם נקודה נצמדה רחוק מ־30 מ׳, או אם תחנת מסוף נצמדה לכביש ראשי (1–2 ספרות). יחס כביש/אווירי לבדו לא משמש. מסלול חשוד מחושב שוב מנקודות כביש סמוכות (`/nearest`, עד 150 מ׳) ונבחר הקצר בלי פרסה; מה שנעשה נשמר (`rt` ברגל ביום, `meta` ב־`road_cache`). `audit/check_invariants.py`: G3 (מסלול חשוד שלא טופל), G4 (רגל שנבנתה לפני הבדיקה), R3/R4 (הבאג והדוגמה הנגדית).
- **נקודות עיגון לתחנות** (הגדרות מערכת → "נקודות עיגון לתחנות", מפתח `stop_anchors`): שם תחנה כפי שמופיע בנתונים → נקודת הניתוב (+ הערה). תנועה בתוך המסוף (הקצה השני עד 500 מ׳ מהתחנה) לא עוברת דרך הנקודה. חל מיד בדשבורד על כל הימים: נסיעות ריקות ביום, לילות ובלוקים שנערכו מחושבים מהנקודה (קובצי היום עצמם לא משתנים; הק״מ מהקובץ מוצג כ"בנתוני היום").
- **נקודות מעבר מאושרות** (הגדרות מערכת, טבלה `via_links`): קטע כביש שמותר לאוטובוסים ולא לרכב פרטי (מחסום / כניסה לתח"צ בלבד), ש־OSRM הציבורי (פרופיל רכב) לא מכיר. מסלול = OSRM עד נקודת הכניסה + אורך הקטע + OSRM מנקודת היציאה, נבחר רק אם קצר יותר ובלי פרסה; נבדק לכל נסיעה שהקטע במרחק עד 2 ק״מ מהקו הישר שלה. עורך מציע, רק מנהל מערכת מאשר (נאכף ב־DB), ורק קטע מאושר משמש לחישוב. חל בדשבורד (כמו נקודות העיגון); ב־`road_cache.meta`: `vpc` (הקטעים שנבדקו) ו־`via`. המלצה לעתיד: פרופיל OSRM לאוטובוסים בשרת עצמי במקום קטעים ידניים.
- **בעיות מסלול** (פס אדום בראש היום, מחשב ונייד): נסיעה ריקה שלא נכנסת בזמן, עיקוף גדול (כביש פי 2.5 מקו אווירי ויותר מ־4 ק״מ) או מסלול חשוד, מקובצות לפי מוצא ← יעד. מכל זוג: מפה, "הצע נקודת מעבר" (שתי נקודות על המפה → הצעה ב־`via_links`, ממתינה לאישור), "הערה" ו"שלח לבדיקה" (טיוטה → `route_reports` ב"שמירה"; קריאה ועדכון רק למנהל מערכת). במיון "שגיאות נתונים תחילה" בעיית מסלול שוקלת יותר מבעיות GPS.
- **מפה לכל שורה בסידור** (`assets/map.js`, Leaflet 1.9.4 בתוך המאגר `assets/vendor/leaflet`, אריחי OSM): נסיעת שירות = מסלול ה־GPS בפועל מ־Open Bus (`siri_vehicle_locations`, נטען בלחיצה) + תחנות הקצה המתוכננות + "סטייה מהמסלול" אם ה־GPS הסתיים רחוק מסוף הקו; ריק = המסלול שחושב (כולל עיגון / קטע מאושר / תיקון הצמדה) + קו אווירי מקווקו, ק״מ, דקות וזמן פנוי; תגבור = ריק לפני + מסלול הקו + ריק אחרי; לילה/חניון = כמו ריק. גיאומטריה נשמרת ב־`road_cache.geom` בפעם הראשונה (עורכים). CSP: `tile.openstreetmap.org`, `open-bus-stride-api.hasadna.org.il`.

## אבטחה ופרטיות (אחרי סקירת האבטחה, 2026-11-16)
- **מפתחות נתונים בגרסאות:** בכל קובץ מוצפן יש `kid`. החלפת מפתח או ביטול גישה של משתמש שהוסר: `pipeline/rotate_key.md`.
- **כניסה:** סיסמה של 10 תווים לפחות. כל מנהל (מנהל מערכת ומנהל מפעיל) חייב אימות דו־שלבי (TOTP): נאכף במסך הכניסה וב־`manage_users` (חדר הבקרה רק מ־session aal2). כל משתמש יכול להפעיל אותו מתפריט החשבון. סיסמה מוחלפת רק דרך `manage_users` (טריגר ב־DB חוסם כל דרך אחרת).
- **דפדפן:** CSP ב־meta (כל הסקריפטים בקבצים, בלי inline), חסימת הטמעה ב־iframe (`assets/frame.js`), ניתוק אחרי 30 דקות בלי פעילות, פונטים מאוחסנים באתר.
- **OSRM (פרטיות):** מרחקי הדרך מחושבים בשרת ההדגמה הציבורי `router.project-osrm.org`, גם מהדפדפן וגם מה־pipeline. השרת מקבל זוגות קואורדינטות (חניונים, תחילת וסוף נסיעות ריקות), בלי שם מפעיל, מספר רכב או משתמש. לשימוש מסחרי מלא כדאי שרת OSRM עצמי או שירות בתשלום; עד אז זה ידוע ומקובל.
- **Nominatim:** מקבל רק את טקסט הכתובת שמוקלד בהגדרות.
- **מה ציבורי:** הקוד, סכמת ה־DB ו־`data/*/days.js` (שם מפעיל, רשימת ימים). הנתונים עצמם מוצפנים.
- **תיק פרטיות** (מסמך הגדרות מאגר, נוהל אבטחה, אירועים, שמירה, ספקים, טיוטות לעו"ד): `yalla-sa-portal/docs/privacy/`. מדיניות הפרטיות (טיוטה) באתר: `privacy.html`, עם קישור ממסך הכניסה והודעה קצרה בכניסה הראשונה.
- **שמירת לוגים:** `private.auth_events` נשמר 24 חודשים ואז נמחק אוטומטית (migration `20261116200000_log_retention`).
- **גיבוי:** `.github/workflows/backup-weekly.yml` כל יום ראשון: `pg_dump` (public, private, auth), בדיקת שחזור ל־Postgres זמני, הצפנה ל־`pipeline/backup/backup-cert.pem`, artifact ל־35 יום. דורש את הסוד `SUPABASE_DB_URL`. מפתח הפענוח רק אצל דוד.
